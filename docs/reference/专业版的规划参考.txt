1. 预期目标：假如你是一个资深的SKILL管理与团队SKILL分发人员，并且公司即将基于内网环境建立SKILL分发与管理：
1.1 文档设计目标：请你为公司提出技术实践方案（1个文档，偏于实践报告的md）、SKILL管理平台的设计要点（1个文档，偏于方法论和支持理论，md格式）以及基于当前给定场景/环境下的实践/搭建pipeline的路线（1个文档，偏于现有场景的md，并且有些内容需要你进行自拟与多情况考虑的模拟）
	- 注：后面的设计内容要尽可能多的参考1.1中的文档设计结果与方案规划书
1.2 角色安排：SKILL站点管理员Admin、SKILL使用者（被分配者，其中这个角色再分为SKILL开发者Developer、SKILL一般使用者User）一共3种
*1.3 场景与功能安排：目前为Skillhub完成以下功能（一个功能区对应菜单栏的一项）
- 1.3.0 （*不是功能）最重要注意：你要设计的产品最终会交付到一点点SKILL知识都不懂，但是会使用Prompt提示工程的纯软件工程师，在术语、用语、超参数、特征设计等方面请注意保证通俗易懂的特性，甚至是可以直接交给各个领域背景下的用户（注：各个领域的客户甚至连编程知识都没有，只会最基本的AI工具对话）。另外系统中尽量最少的专业术语，哪怕有一点点术语（大概率也是在效能与质量评估那里）也必须配上通俗解释以及计算方法说明
- 1.3.1 SKILL生成与构建功能模块：基于用户的各种输入制作SKILL，要求满足SKILL的一般规范（参考上面的链接或者是菜鸟教程），具体包含：
	- 允许用户选择SKILL的基本特征与超参数，包括但不仅限于：使用背景、SKILL别名、生成SKILL的额外Prompt、当前SKILL会用到哪种/哪些种Vibe Coding工具（可多选）、SKILL的生成过程是否使用MCP
		- 使用背景限制在以下方面：医疗健康Medical、政务信息Government、新闻传媒Reviews、教育Education、交通Traffic、金融Financial一共6个
		- Vibe Coding工具限制在以下几种：Github Copilot, Claude Code, OpenCode, Qoder（原通义灵码）, ZCode, TRAE（字节）, Codex, Continue以及国内支持的AI辅助工具（豆包、智谱轻言、文心一言3种）一共11种
		- 支持的AI智能体就主打国内吧（不过好像上述的Vibe Coding工具就够多了）
	- 用户输入要求：文本（txt, Word, PPT等10多种文本格式+没有任何后缀的file文件）、图像（png, jpg/jpeg, svg等5种以上的图像格式）、表格与结构表（Excel, SQL, csv等5种以上表格格式）、其他可解析的程序脚本（javascript, php, html, java/class/jar, C/C++, python等至少9种语言）
	- 根据SKILL的标准结构（1个文件夹+1个指引md），文件夹里的所有数据、格式文件等都只能来源于用户给出的数据与信息，不可过多延展，指引文件也应该满足SKILL制作的标准规范
	- 当SKILL的生成使用MCP时，要参考当前的MCP的作用与具体使用情况/背景对SKILL的生成进行增强，提升SKILL在多个语境与多个工具下的泛化能力（请参考以上链接与更多网络资源如菜鸟教程）
	- SKILL生成后（准备输出时），支持以下3种模式：（或小于等于4种）
		- 链接调用与分享（类似镜像）
		- 直接下载SKILL包
		- 作为服务/其他可分发给各个开发使用者的库/包/可直接下载与调用的资源格式（请严格学习SKILL在具体市场背景下是如何使用的，进行设计）
- 1.3.2 SKILL质量评估：模拟真实场景进行SKILL的通信性能与任务效能测试，性能/效能指标请依据当前市场中SKILL生成与使用的已有经验、常见SKILL市场的已知指标与相关专业文献进行索引，选择合适当前系统的指标
	- 质量评估场景在1.3.1中规定的6种，关于数据集这里规定：统一将接下来的数据集分为3大类：用于质量评估的参与SKILL测试的场景数据表集合（主要是各种业务数据，请尽可能索引整个市场，挖掘数据制作成各种SQL表和其他类型的结构化数据，可以非SQL但也需要SQL做索引）、围绕SKILL生成管理分发等主要功能的SKILL操作型索引表集合（主要是索引到各个SKILL相关、执行SKILL管理操作与分发操作、存储操作等等的SKILL操作类型数据表合集）、围绕整个平台底座的系统型数据表（包含各种重要和不重要功能的杂项表，例如MCP相关的表、知识库相关的表、登录认证相关的基础表等等，往往是支持平台的底座型表格）
	- 质量评估有表有图，以类似数据大屏的形式展现出对于SKILL评估最有用处，当前市场用户最关心的要素与特征
	- 必要地给出指标计算方法、名词解释与方法论（这一板块可以适当专业一点，体现SKILL的知识）
	- 如果使用了MCP的SKILL，也尽量围绕MCP进行评估（这一项只针对使用MCP的SKILL）
	- 质量评估与测试也尽可能考虑各个超参数的单因素/多因素影响以及各种AI辅助编程工具
- 1.3.3 SKILL管理与分发：这一模块主要是面向使用当前SKILL站点的开发者/用户，和1.3.1，1.3.2一样讲求通俗易懂，包含的管理与分发操作有：
	- SKILL的手动增加（非平台生成）、内容编辑（基于已有SKILL或者新建，按照方便用户编辑的风格设计，通俗易懂）、超参数编辑、质量规范编辑（这里需要通俗化解释）、SKILL的删除、SKILL一览表（条件查询）
		- SKILL的手动增加包含：压缩包导入与解析、在线工作台输入各种SKILL文件（文本和程序语言支持在线编辑器、然后允许所有模态文件的文件分级导入，这里的
分级可以理解为windows平台建立文件夹，在文件夹中导入文件的文件管理器模式）
		- SKILL的增加和修改允许修改的超参数也包括适用的Vibe Coding工具与AI智能体
	- SKILL的管理中需要联系其他所有SKILL的相关功能，如质量评估
	- SKILL管理的特殊功能"SKILL关联强化"：包含：
		- 基于已有的同一场景的多个SKILL新生成一个具有多个功能/功能聚合的SKILL
		- 基于已有的某个SKILL + 用户再给出的一些自定义资源（依旧是文件管理器模式），生成一个与原来功能更强的SKILL
			- 推荐：虽然每个SKILL的资源文件夹是有源的限制性输入（只来源于用户输入），但是请尽可能发散地设计各种文件格式、文件索引与优异地指引文档，尽可能满足用户所需要的各种模型
			- 以上的"关联强化"对SKILL的改变也视作编辑，所以注意事项与上面的编辑功能一样
	- SKILL的分发：这一部分要尽可能参考当前市场对SKILL的分发的一些新技术，发挥活性与创造力（例如参考：https://www.runoob.com/skills/skills-publish.html），而且需要你给出支持Gitlab/Github的SKILL分发链接与方法
		- 预期规划功能：给出分发链接供管理员/开发者分享给同事、允许多种SKILL文件格式的分发与多形式的有效传输（尽可能多参考市场）
- 1.3.4 SKILL+MCP支持下的基于当前的SKILL和场景数据集的知识库建立，包含
	- 压缩成知识图谱格式的SKILL库，其中知识库可以以常用格式导出，知识库的建立可以按照场景、知识本体等，确保建立的知识库可以用于前面的所有功能（提示：各个模块之间应在应建立关联的地方建立强关联）
		- 选择合适的知识图谱工具进行可视化，另外动态图要尽可能让各个图例、线条清晰，知识图谱与知识库应该局限地来源于数据集、场景集、SKILL集合，不能有外在干涉（建议可视化策略：展示一个多维网络的知识图谱，然后对于每个场景/自定义的知识分区再进行分区域可视化（通过放大最大的母知识图谱也可））
		- 知识图谱/知识库应该与前面的哪些模块建立关联，知识图谱与MCP的工程关系与数理关系，与SKILL之间的管理分配分发、任务效能和通信性能等都要考虑并且展现。也能保证知识库能够在前面的应该使用的功能中被使用
		- 知识图谱/知识库可以导出、可以从选定的几个SKILL（自定义）中生成
