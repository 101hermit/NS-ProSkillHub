# PSKH 01 · 需求与定位

## 1. 一句话定位

**面向 Skill 的多功能 Agent 平台。** 在标准版（库管理 + 单点实测）之上，把"实测"升级为
**实验设计**，把"评估"升级为**知识级洞见**：
多 Agent × 多 MCP × 多场景的连通与实测矩阵、三张实验表、知识图谱、统计检验与多准则决策。

共享基线见仓库根 [docs/00](../../docs/00-三系统总纲与递进设计.md) 起 8 篇。

## 2. 为什么需要专业版

标准版回答"这个 Skill 行不行"。专业版回答的是**比较与归因**：

| 真实问题 | 属于哪类 | 专业版的答案 |
| --- | --- | --- |
| 同一个 Skill 在 3 个模型上差多少？ | 纵向比 Agent | `SKILL_SCAN`：一个 Skill × 多 Agent × 多超参 |
| 5 个候选 Skill 在同一条件下谁最强？ | 横向比 Skill | `SKILL_COMPARE`：多 Skill × 固定条件 |
| temperature 0 和 0.7 到底有没有差？ | 斜向比超参 | 参数网格 + 假设检验（p 值与效应量） |
| 这些 Skill 之间有隐性关联吗？ | 知识级 | 知识图谱（分类 / 场景 / 标签 / 相似） |
| 哪些组合根本连不上？ | 工程 | 连通矩阵（Agent × MCP 逐格 + 归因） |

**一句话判据**：专业版能给出"哪个更好、差多少、为什么"三者齐全的结论。

## 3. 需求清单

| # | 需求 | 判据 |
| --- | --- | --- |

| R11 | 必要指标含任务效能与通信性能两维 | 9 项指标沿用标准版口径 |

### 3.2 应该（P1）

| # | 需求 | 说明 |

### 3.3 明确不做

- ❌ 训练 / 微调模型
- ❌ 外部向量库 / 图数据库（只用关系表 + 内存算法）
- ❌ 分布式调度 / 消息队列（矩阵串行，可解释、可复现）
- ❌ 实体消歧、语义嵌入（是"轻图谱"，规则生成）

## 4. 场景剧本

### 场景 A：三家模型跑同一个 Skill

1. 「实测中心」→ (b) Skill 维度扫描 → 选 `pdf`、勾 `deepseek-flash` + `glm-4-flash` + `ark-kimi`、
   发散程度勾 `0` 与 `0.7`、场景「通用」
2. 执行 → 每格给出输出 + 推理 + 9 项指标
3. 「看分组对比」→ 按 Agent 一栏直接看出谁更强、TOPSIS 排名第 1 是谁
4. 「知识级分析」→ 选 `HYPOTHESIS` → 得到 t / p / Cohen's d 与"是否显著"的中文结论

### 场景 B：五个候选 Skill 同台竞技

1. (c) Skill 横向对比 → 勾 5 个 Skill，固定单 Agent + 单参数 + 单场景
2. 执行 → 5 个单元；对比页「按 Skill」表按 TOPSIS 排好名次
3. 点开分数最低的那格，看推理过程为什么没答到点上

### 场景 C：先确认"能不能连上"

1. 「连通矩阵」→ 一键探活 → 4 Agent × 2 MCP = 8 格
2. 不通的格子给出三类归因之一（没走代理 / 缺根证书 / 服务没起）
3. 修好后重新探活，全绿再开始跑矩阵

### 场景 D：这批 Skill 之间有什么关联

1. 「知识图谱」→ 重建 → 639 实体 / 719 关系
2. 下拉到「医疗健康」→ 只看该场景的 Skill 与它们的分类/标签
3. 点节点看详情；右侧搜一个 Skill 看它的相似推荐
4. 导出 GraphML 丢给外部工具继续分析

## 5. 增量迭代记录（原型 + 定制化敏捷 + 增量）

| 增量 | 范围 | 产出 | 调整 |
| --- | --- | --- | --- |
| 增量 1 | 连通矩阵 | 4×2 热力图 + 逐格归因 | 探活原按 200 才算通 → 改为任何 HTTP 响应都算通道可达（401 也说明网络通） |
| 增量 2 | 实验矩阵 + 分组对比 | 两种矩阵类型 + 三张分组表 + TOPSIS | 单元数原无上限 → 加 120 上限（防止误点打满共享模型） |
| 增量 3 | 知识图谱 | 实体/关系重建 + SVG 力导向 + 三种导出 | 唯一键冲突（重复关系）→ 重建前按 `(src,dst,type)` 去重 |
| 增量 4 | 知识级分析 | 6 种方法 + 中文结论 | 假设检验原只有 1 组就报错 → 加"按用例回退"分组 |
| 增量 5 | 专业级 Agent 注册 | 4 个 Agent（含 3 家厂商） | 缺 Key 时不再报错中断，而是回退离线桩并标注原因 |

## 6. 与另两个版本的关系

```
ESKH（资源站）
  ⊂ SSKH（+ 库语义 + 单点实测 + 统计口径评估）
      ⊂ PSKH（本版本：+ 连通矩阵 + 实验矩阵 + 知识图谱 + 知识级分析）
```

**本版本必须守住的边界**：
1. 不训练模型、不引入向量库 —— 只做"用"与"评"；
2. 图谱不追求语义级（不消歧、不嵌入），保持"规则可解释"；
3. 矩阵串行执行 —— 宁可慢，也要"可复现、可解释"。
