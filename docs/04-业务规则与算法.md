## 1. 连通性判定

```
agentOk  = agentPort.probe(code).ok
mcpOk    = mcpPort.probe(code).ok
cell.ok  = agentOk && mcpOk
cell.latencyMs = agentLatency + mcpLatency
```

`probe().ok` 的口径：**任何 HTTP 响应（含 401/403/404）都算 true**；连接失败 / TLS 失败 /
DNS 失败才算 false，并把归因写进 `detail`（三类：没走代理 / 缺根证书 / 服务没起）。

**为什么 401 也算通**：401 意味着 TLS 握手与 HTTP 往返都成功了，只是没带对凭据 ——
这对"网络能不能到"这个问题来说，就是"能到"。

## 2. 实验矩阵的规模与展开

```
planned_cells = |skills| × |agents| × |mcps| × |paramGrid| × |cases|
```

`paramGrid` 是 `{key: [v1, v2, …]}`，笛卡尔展开：

```
[{temperature:0.0}, {temperature:0.7}]
× [{top_p:1.0}]
= [{temperature:0.0, top_p:1.0}, {temperature:0.7, top_p:1.0}]
```

规则：
1. `paramGrid` 只接受 `temperature` / `top_p` / `max_tokens` 三个键（其它键忽略，避免脏参数）；
2. 空网格填默认 `temperature: [0.3]`；
3. `matrix_type = SKILL_COMPARE` 时**强制取每维第一个值**（单 Agent、单参数），
   因为横向对比要固定条件才有意义；
4. `skill_ids` 为空 → 取库里第一个 Skill（让页面第一次点击就能跑起来）；
5. `cases` 为空 → 服务端自拟：
   - `auto-1`「用一句话说明这份手册能帮我做什么，并给出第一步该怎么做。」
   - `auto-2`「按手册给我一个可执行的三步方案，每步一句话。」
   - `auto-3`（非通用场景时）「在「X」场景下，这份手册最需要注意什么？」
6. `planned_cells > 120` → 400，`msg` 明确说"减少哪个维度"。

## 3. 单元打分（与标准版同口径）

```
correctness = F1(output, expected)          weight 3
coverage    = 期望 token 被覆盖的比例        weight 2
completeness= min(1, |output|/|expected|)    weight 1
task_success= coverage≥0.5 && F1≥0.4 ? 1:0   weight 2
consistency = 调用成功 ? 1 : 0               weight 1
ttft        = 1 − min(1, ttft/2000)          weight 1
latency     = 1 − min(1, latency/30000)      weight 1
throughput  = min(1, tokens/s ÷ 50)          weight 1
success     = 调用成功 ? 1 : 0               weight 1
────────────────────────────────────────────────────
score = Σ(wᵢvᵢ)/Σwᵢ × 100        （Σwᵢ = 13；任务效能占 9/13 ≈ 69%）
```

## 4. 分组对比与 TOPSIS

```
按 skill / agent / params 三组聚合：
   avg_score          = 组内 score_total 的均值
   success_rate       = DONE 单元数 / 组内单元数
   latency_efficiency = 1 − min(1, 组内平均时延 / 30000)
三准则 TOPSIS（全部"越大越好"）：
   向量归一化 → 乘权重 [3, 2, 1] → 正/负理想解 → 相对贴近度
按贴近度降序给 rank
```

**为什么 TOPSIS 而不是简单排名**：简单排名只看均分，会把"偶尔很高但极不稳定"的 Skill
排到前面。TOPSIS 让"成功率"和"时延"也参与，结果更接近工程直觉。

## 5. 知识图谱生成规则

### 5.1 实体（639 个）

| 类型 | 生成规则 | 权重 |
| --- | --- | --- |
| `SKILL` | 每个 Skill 一个，code = `skill:<skill_id>` | 1.0 |
| `CAPABILITY` | 8 个工程类分类 | 2.0 |
| `SCENE` | 6 个行业分类 + 6 个 `scene:<code>` 节点 | 2.0 / 2.5 |
| `TAG` | 所有 Skill 标签去重（~230） | 0.6 |
| `AGENT` / `MCP` | 接入注册表 | 1.0 |

**来源被硬性限制在三处**：Skill 库、分类本体、接入注册表。不允许外部注入 ——
这是"知识来自数据，不来自想象"的具体落地。

### 5.2 关系（719 条）

| 关系 | 规则 | 权重 |
| --- | --- | --- |
| `BELONGS_TO` | Skill → 分类（分类非 `general`） | 1.0 |
| `IN_SCENE` | Skill → 场景（场景非 `general`） | 1.0 |
| `HAS_TAG` | Skill → 每个标签 | 0.6 |
| `EVALUATED_BY` | Skill → 实测过的 Agent | 1.0 |
| `SIMILAR_TO` | 同分类且共享标签的两 Skill | 共享标签数 |

**生成顺序**：先按 Skill 逐条生成（数量线性），再做"同分类两两配对"（限制 6000 对，
避免 375² 爆炸）。配对时计算共享标签集，非空才建边，`evidence` 写"共享标签：a/b"。

**去重（必须）**：`kg_relation` 有 `(src_code,dst_code,relation_type)` 唯一键，
重建前用 `LinkedHashMap` 按三元组去重。实测踩过：某 Skill 的标签里有重复项
（如 `tag:-` 出现两次）导致 5001。

### 5.3 场景下钻

```
若 scene 非 global：
    allowed = {scene:<scene>} ∪ {skill:<id> | skill.scene_code == scene}
    遍历关系：src 或 dst 在 allowed 中 → 保留该边，并把另一端也纳入节点集（一跳邻居）
否则：
    allowed = 全部实体
```

然后按度数降序取前 `limit` 个节点（默认 150，上限 300），只保留两端都在节点集里的边。
**按度数排序**是为了把"枢纽节点"留在图上，而不是随机截断。

## 6. 六种分析方法

### 6.1 DESCRIBE（描述统计）

`n / mean / std / min / max / median` + 6 桶等宽直方图。
结论口径：**标准差 > 均值一半** → 提示"结果高度依赖条件"。

### 6.2 HYPOTHESIS（Welch t 检验）

```
t  = (x̄₁ − x̄₂) / √(s₁²/n₁ + s₂²/n₂)
df = (s₁²/n₁ + s₂²/n₂)² / [ (s₁²/n₁)²/(n₁−1) + (s₂²/n₂)²/(n₂−1) ]
d  = (x̄₁ − x̄₂) / √((s₁²+s₂²)/2)          ← Cohen's d
p  = 2 · (1 − Φ(z*))                      ← z* 带 Edgeworth 修正
显著 = p < 0.05
```

**分组不足时的回退**：若 `groupBy` 只有 1 组（例如只跑了一个 Agent），
自动改为**按用例**（`case_code`）分组再比 —— 不同用例的分数差异也是合法比较。
仍不足 2 组才报 409/1300，并建议"用至少 2 个 Agent 或 2 条用例"。

结论话术：
- 显著 → "换条件确实会改变表现，值得单独说明"；
- 不显著 → "证据不足以说明有影响，建议增加样本量"。

### 6.3 TOPSIS

两准则：`[均值(权重 3), 稳定性(权重 1)]`，稳定性 = `1/(1+方差)`。

### 6.4 CLUSTER（k-means）

`k = min(3, max(2, n/3))`，中心初始化取等距样本，最多 30 轮，无变化即停。

### 6.5 REGRESSION（一元最小二乘）

```
slope = Sxy/Sxx,  intercept = ȳ − slope·x̄,  R² = Sxy²/(Sxx·Syy)
```
结论口径：`R² < 0.1` → "时延几乎解释不了分数差异，差异更可能来自 Skill/Agent 本身"。

### 6.6 AHP（层次分析法）

预置 3×3 判断矩阵（正确性 > 覆盖 > 时延）：

```
     正确性  覆盖   时延
正确性  1     3     5
覆盖   1/3    1     3
时延   1/5   1/3    1
```

几何平均法求权重 → 计算 `λmax` → `CI = (λmax − n)/(n−1)` → `CR = CI / RI`（n=3 时 RI=0.58）。
结论口径：`CR < 0.1` 才算判断前后一致。
